# Safety analysis traceability workflow

This project now supports a lightweight TRLC + SysML v2 safety-analysis chain inspired by the PlantUML/TRLC/Lobster workflow described in the reference project.

The intended chain is:

```text
TRLC FailureMode
→ SysML v2 FTA/root-cause model
→ SysML BasicEvent comments
→ TRLC ControlMeasure
→ placeholder traceability checker
```

## Files

```text
requirements/failure_modes.trlc
requirements/control_measures.trlc
tools/check_safety_analysis_traceability.py
```

## Responsibility split

Failure modes are explicit safety-analysis records in TRLC. They are not hidden in JSON and they are not pretended to be magically generated by SysML.

SysML v2 provides the architectural evidence: where the failure can propagate through behavior, which root/basic events are considered, and which architectural mechanisms are involved.

Control measures are explicit TRLC records that mitigate SysML-declared basic events.

## Parser-safe SysML comments

The SysML file uses official SysML v2 actions and successions, plus parser-safe comments:

```sysml
// trlc-failure-mode: AcpdCddSafety.MissingAdcNotification
// safety-basic-event: AcpdCddSafety.BE_MissingAdcNotification
```

The comments are intentionally similar in role to PlantUML aliases in the reference workflow: they provide stable IDs that a checker can connect to TRLC records.

## Run the placeholder checker

```bash
python tools/check_safety_analysis_traceability.py
```

It generates:

```text
reports/safety_analysis_traceability.json
reports/safety_analysis_traceability.md
```

The checker verifies:

- every TRLC FailureMode is referenced by at least one SysML FTA/root-cause model
- every SysML failure-mode reference points to an existing TRLC FailureMode
- every SysML BasicEvent has at least one TRLC ControlMeasure
- every ControlMeasure mitigates an existing SysML BasicEvent

## Why this is better than the previous JSON catalogue

The earlier JSON catalogue was useful for prompt generation, but it blurred the ownership of failure modes.

This workflow is cleaner:

```text
Failure modes: engineer-owned TRLC artefacts
Propagation/root-cause evidence: SysML v2 architecture model
Control measures: engineer-owned TRLC artefacts
Traceability verification: CI-friendly checker
```

Later, this placeholder checker could be replaced or complemented by Lobster/Bazel without changing the conceptual model.
